# 基础概念：构建音乐播放器

本文档旨在帮助你理解构建一个数字音乐播放器所需的核心概念，特别是围绕 FFmpeg 和嵌入式 Linux 环境。

## 1. 什么是数字音频？

声音本质上是一种模拟信号（连续的波）。要让计算机处理声音，必须先将其“数字化”。这个过程主要涉及以下几个关键参数：

-   **采样率 (Sample Rate):**
    每秒对模拟声波进行采样的次数。单位是赫兹 (Hz)。例如，CD 音质的采样率为 44100 Hz (或 44.1 kHz)，意味着每秒采集 44100 个数据点。采样率越高，记录的声音细节越丰富，高频部分还原得越好。

-   **位深度 (Bit Depth):**
    描述每个样本的精度，即用多少位（bit）来存储一个采样点的数据。例如 16-bit 或 24-bit。位深度越高，表示声音振幅的级别就越多，动态范围（最响和最轻声音之间的差距）就越大，声音听起来就越细腻。

-   **声道 (Channels):**
    音频流的数量。常见的有单声道 (Mono, 1个声道) 和立体声 (Stereo, 2个声道)。

-   **PCM (Pulse-Code Modulation - 脉冲编码调制):**
    经过采样和量化后，**未经压缩的原始数字音频数据**就是 PCM 数据。这是最基础的数字音频格式，也是音频解码后，最终需要送给硬件声卡进行播放的数据格式。

## 2. 音频是如何存储和分发的？

原始的 PCM 数据非常庞大（例如，一首4分钟的CD音质立体声歌曲约40MB），不便于存储和网络传输。因此，我们需要对它进行压缩。

-   **编码 (Encoding) / 编解码器 (Codec):**
    -   **编码**是将 PCM 数据进行压缩的过程。
    -   **解码**是将其还原的过程。
    -   实现特定编码/解码算法的程序就是**编解码器 (Codec)**。
    -   **有损压缩 (Lossy):** 压缩时会丢弃一部分人耳不敏感的信息，以换取极高的压缩率。文件大小显著减小，但无法完全还原成原始数据。常见格式：**MP3, AAC, OGG**。
    -   **无损压缩 (Lossless):** 压缩后可以 100% 完美地还原成原始 PCM 数据，压缩率相对较低。常见格式：**FLAC, ALAC, APE**。

-   **容器 (Container):**
    -   一个“盒子”或“包装”，用来存放编码后的音频数据流、元数据（如歌手、专辑名、封面图片）以及可能的其他数据流（如视频流）。
    -   **重要区别：** 容器格式 **不等于** 编码格式。例如，一个 `.mp4` 文件里的音频流可能是 AAC 编码，也可能是 MP3 编码。
    -   常见音频容器：`.mp3` (通常只包含 MP3 音频流), `.m4a` (通常包含 AAC 音频流), `.flac`, `.ogg`。

## 3. 音乐播放的完整流程

一个音乐文件从磁盘到扬声器，大致经历以下步骤：

1.  **解封装/解复用 (Demuxing):**
    -   **作用:** 读取容器文件 (如 `.m4a`)，并将里面的音频流（AAC编码）从元数据（封面图片等）中分离出来。对于音乐播放，我们只关心音频流。

2.  **解码 (Decoding):**
    -   **作用:** 将从容器中分离出来的、经过压缩的音频流（如 AAC 码流）通过相应的解码器（AAC 解码器）还原成原始的 **PCM 数据**。

3.  **重采样/格式转换 (Resampling / Format Conversion):**
    -   **作用:** 解码后的 PCM 数据格式（如 44.1kHz, 24-bit, Stereo）可能不被你的硬件声卡直接支持。例如，imx6ull 的声卡可能只接受 48kHz, 16-bit, Stereo 的数据。这个步骤就是将解码后的 PCM 数据转换成硬件支持的格式。

4.  **音频输出 (Audio Output / Sink):**
    -   **作用:** 将格式转换好的 PCM 数据，通过操作系统提供的音频接口（在 Linux 上通常是 **ALSA** - Advanced Linux Sound Architecture），发送给声卡驱动。
    -   **硬件:** 声卡上的数模转换器 (DAC) 将数字 PCM 信号转换回模拟电信号，驱动扬声器或耳机发出声音。

## 4. FFmpeg 在其中扮演的角色

FFmpeg 是一个功能极其强大的开源多媒体处理框架，它将上述复杂的流程封装成了相对简单的 API，让你不必关心每种格式的内部细节。

-   **`libavformat` 模块:**
    -   负责 **解封装 (Demuxing)**。它可以打开几乎所有常见的媒体容器文件（`avformat_open_input`），分析其中的流信息（`avformat_find_stream_info`），并从中读取出压缩的数据包 `AVPacket`（`av_read_frame`）。

-   **`libavcodec` 模块:**
    -   负责 **解码 (Decoding)**。它能根据流信息找到对应的解码器（`avcodec_find_decoder`），然后将 `libavformat` 读取出的 `AVPacket` 解码成原始的 PCM 数据帧 `AVFrame`（`avcodec_send_packet`, `avcodec_receive_frame`）。

-   **`libswresample` 模块:**
    -   负责 **重采样和格式转换**。如果解码后的 `AVFrame` 格式不符合硬件要求，可以用这个模块进行转换。

-   **`libavutil` 模块:**
    -   提供核心的工具函数和数据结构，如 `AVFrame` (存储解码后的数据), `AVPacket` (存储解码前的数据包) 等，贯穿整个 FFmpeg API 的使用过程。

### 总结

你的播放器程序的主要工作，就是调用 FFmpeg 的 API 来完成 **解封装** 和 **解码** 这两个核心步骤，得到 PCM 数据。然后，你需要自己编写代码，将这些 PCM 数据通过 Linux 的 **ALSA** 接口喂给 imx6ull 的声卡，最终实现播放。
